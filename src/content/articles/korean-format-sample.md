## 걷다가 떠오른 한 문장

어떤 생각은 책상 앞보다 길 위에서 선명해집니다. 방금 지나친 풍경, 끝내 답하지 못한 질문, 서로 관계없어 보이던 두 문장이 잠시 같은 방향을 가리키는 순간이 있습니다.

그럴 때 처음부터 완성된 글을 쓰려고 애쓰지는 않아도 됩니다. **무엇이 궁금했는지**를 남기고, *왜 그 질문이 마음에 걸렸는지*를 덧붙이는 것으로 시작할 수 있습니다. ~~처음부터 빈틈없는 결론이 필요하다~~는 생각은 잠시 지워두어도 좋겠습니다.

이 문단과 앞 문단 사이의 여백은 글의 호흡을 구분합니다. 짧은 단상은 여기서 끝날 수도 있고, 같은 질문을 오래 붙잡으면 연구 노트가 될 수도 있습니다.

## 관찰과 해석을 나누기

기록할 때에는 관찰한 사실, 그 사실에 대한 해석, 아직 확인하지 못한 내용을 나누어 적어봅니다. 이 구분은 결론을 미루기 위한 것이 아니라, 다음에 무엇을 확인할지 찾기 위한 장치입니다.[^observation]

### 순서 없는 목록

- **관찰:** 직접 보거나 읽은 것은 무엇인가?
- **해석:** 관찰을 바탕으로 어떤 생각을 했는가?
- **질문:** 아직 설명되지 않은 부분은 무엇인가?
  - 다시 찾아볼 자료
  - 다른 설명이 가능한 지점

### 순서 있는 목록

1. 떠오른 문장을 짧게 적습니다.
2. 문장의 근거와 반례를 함께 찾습니다.
3. 확인한 내용과 추측을 구분합니다.
4. 나중에 다시 읽을 수 있도록 날짜와 맥락을 남깁니다.

#### 작은 메모

본문 속 짧은 식별자나 파일 이름에는 인라인 코드인 `notes.md` 같은 표기를 사용할 수 있습니다. 관련 자료는 [영문 게시글 목록](/articles/)처럼 링크로 연결할 수 있습니다.

> 좋은 기록은 모든 것을 설명하는 기록이 아니라,
> 다음 질문을 시작할 수 있게 해주는 기록일지도 모릅니다.
>
> — 인용문 서식을 보여주기 위해 작성한 예시 문장

## 표로 정리하는 메모

아래 표의 내용과 횟수는 모두 서식 확인용 가상 값입니다.

| 구분 | 기록할 내용 | 예시 횟수 |
| :--- | :--- | ---: |
| 관찰 | 직접 확인한 장면이나 자료 | 3 |
| 해석 | 관찰에서 출발한 설명 | 2 |
| 질문 | 추가로 확인해야 할 부분 | 4 |

표는 반복되는 항목을 비교할 때 사용하고, 맥락이 중요한 내용은 문단으로 풀어쓸 수 있습니다.

## 코드와 수식이 필요한 순간

### 코드 블록

메모를 간단한 자료형으로 표현하면 다음과 같습니다. 실제 서비스의 구현이 아닌 TypeScript 문법 강조 예시입니다.

```ts
type Note = {
  question: string;
  observations: string[];
  nextStep?: string;
};

const note: Note = {
  question: "이 설명을 다른 자료에서도 확인할 수 있을까?",
  observations: ["원문에 제시된 근거를 먼저 기록한다."],
  nextStep: "반대되는 사례가 있는지 찾아본다.",
};

console.log(note.question);
```

### 인라인 수식과 독립 수식

확인한 항목 수를 $k$, 전체 항목 수를 $n$이라고 적을 수 있습니다. 예를 들어 $n > 0$일 때, 확인한 항목의 비율 $r$은 다음과 같이 표현됩니다.

$$
r = \frac{k}{n}, \qquad 0 \leq k \leq n
$$

이 식은 수식 표시를 위한 단순한 예시입니다. 확인한 항목의 비율이 높다는 사실만으로 설명의 정확성이나 연구의 신뢰도가 보장되는 것은 아닙니다.
